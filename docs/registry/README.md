### Как опубликовать

Страницы собираются из этих же .md — руками их верстать не надо и НЕЛЬЗЯ:
две копии одного текста разъезжаются на первой правке, и разъехавшуюся
заметит проверяющий, а не мы.

```
node docs/registry/build-site-pages.mjs
```

Получится готовая папка `out/site/reestr-po/` — залить её целиком в корень
сайта china-ru.ru (сайт на Битриксе, репозиторий `D:/Claude/China-Bitrix`).

```
out/site/reestr-po/  →  <корень сайта>/reestr-po/
  index.php                        оглавление
  funkcionalnye-harakteristiki/index.php
  ustanovka-i-ekspluataciya/index.php
  zhiznennyy-cikl-i-podderzhka/index.php
  stoimost/index.php
  regdoc.css                       стили раздела
  .htaccess                        запрет листинга каталога
```

Страницы обычные битриксовые: `bitrix/header.php`, содержимое, `bitrix/footer.php`.
Ни компонента, ни инфоблока, ни правок шаблона не требуется — раздел
переносится одной папкой и живёт сам по себе.

🔥 Адрес выбран `/reestr-po/`, а не `/docs/`: в репозитории China-Bitrix
папка `docs/` занята внутренней документацией по архитектуре, и раздел
с таким именем на сайте однажды выложил бы её наружу.

После заливки проверить: все пять адресов открываются без авторизации,
в приватном окне и с телефона. Требование реестра — свободный доступ.

## Про лицензии инфраструктуры — что здесь важно, а что нет

Подаче **ничего из перечисленного не мешает**. ПП РФ № 1236 не запрещает
использовать копилефт и не требует, чтобы вся среда исполнения была под
разрешительными лицензиями. Требование одно и денежное: выплаты в пользу
иностранных лиц по лицензионным договорам — **менее 30 % выручки**
от реализации ПО за год. AGPL, SSPL и RSALv2 выплат не предполагают вовсе,
поэтому этого порога не касаются. В реестре полно продуктов на PostgreSQL,
Linux и nginx — среда исполнения на статус не влияет.

Что было важно на самом деле — **точность собственных формулировок**.
Документ 01 в первой редакции утверждал, что вся общесистемная обвязка идёт
под свободными лицензиями. Для Redis с версии 7.4 (RSALv2 + SSPL) и MinIO
(AGPL-3.0) это неверно, а неточное утверждение в поданном документе — проблема
куда более реальная, чем сама лицензия. Формулировки исправлены: теперь
документ прямо называет лицензии, проводит границу между составом ПО
и средой исполнения и объясняет, почему ограничения SSPL и AGPL к продукту
не применяются (он использует эти службы внутри, а не предоставляет их
функциональность третьим лицам).

| Компонент | Лицензия | Влияние на подачу |
|---|---|---|
| PostgreSQL 16, Meilisearch, nginx, Node.js, Docker | PostgreSQL License, MIT, BSD, Apache-2.0 | нет |
| `redis:7-alpine` (7.4+) | RSALv2 + SSPL | нет: выплат не требует, используется как внутренний кеш |
| `minio/minio` | AGPL-3.0 | нет: отдельный сетевой сервис, продукт с ним не линкуется |
| Библиотеки в составе ПО (24 шт.) | MIT, Apache-2.0, BSD, ISC | нет |
