## 7. 🔴 Единственный настоящий блокер

Условие «б» — программное обеспечение должно быть введено в гражданский
оборот. Для ФИПС это неважно, там депонируют код; для реестра важно.

На сегодня ветка `main` не запушена в `origin`, рабочего экземпляра этого
монорепозитория нет. Заявление описывало бы продукт, которого нет в обороте,
и дать доступ по разделу 6 было бы нечем.

**Что нужно сделать:**

1. Сервер: x86-64, Linux, российский хостинг (размещение в РФ прямо
   заявлено в документе 01).

   ⚠️ Решено разворачивать на том же VPS, где работает china-ru.ru на
   Битриксе, — через наложение `docker-compose.proxy.yml`. Тариф на
   27.10.2026 — 2 vCPU, 4 ГБ RAM, 70 ГБ диска; память на время
   развёртывания и экспертизы расширяется до 6 ГБ. Её должно хватать
   **обоим**: Битриксу с его PHP и MySQL и нашему стеку из восьми
   контейнеров (Postgres, Redis, Meilisearch, SeaweedFS, api, web, admin,
   nginx). Свободную память проверить до запуска: `free -h`. Запас меньше
   4 ГБ — поднимать нельзя, OOM-killer придёт за действующим сайтом, а не
   за нашим. Порядок — `docs/deploy-po-runbook.md`.

2. Поддомены под экземпляр: **`po.china-ru.ru`**, api и admin вложены в него
   (`api.po.china-ru.ru`, `admin.po.china-ru.ru`). Основной домен занят
   действующим сайтом.

   🔥 Вложенность, а не три соседних поддомена. Витрина и API делят cookie
   сессии, значит `COOKIE_DOMAIN` — их общий родитель. У соседей
   app/api/admin общий родитель только `china-ru.ru`, и refresh-токены
   платформы уходили бы в каждый запрос к действующему сайту на Битриксе.
   При вложенности общий родитель — сам `po.china-ru.ru`.

3. Запушить `main`. Деплой из GitHub Actions — только ручной запуск и
   только с наложением (`.github/workflows/deploy.yml`); для него нужны
   секреты `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_PATH`.
   Первое развёртывание делается руками по `docs/deploy-po-runbook.md`.
4. Развернуть по документу 02 и **пройти его по шагам**: инструкция написана
   по коду, но на живом сервере не прогонялась. Что разойдётся — сразу
   поправить в документе, он публичный и его будут читать.
5. Наполнить демонстрационными данными, завести три учётные записи.

Пункт 4 — не формальность. Если эксперт пойдёт по опубликованной инструкции
и она не сработает, это хуже, чем её отсутствие.
