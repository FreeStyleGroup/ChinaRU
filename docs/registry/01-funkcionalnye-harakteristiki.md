**Документ подготовлен** в соответствии с требованиями Постановления Правительства

## 1. Назначение

Программное обеспечение представляет собой веб-платформу электронной торговли
(маркетплейс) для сегмента B2B, предназначенную для организации сделок между
поставщиками промышленного оборудования и комплектующих и их покупателями —
юридическими лицами и индивидуальными предпринимателями.

Платформа обеспечивает полный цикл взаимодействия: публикацию товарных
предложений продавцами, поиск и подбор оборудования покупателями, оформление
и сопровождение заказа, проведение закупочных процедур в форме тендеров,
а также сопутствующие сервисы — публикацию вакансий и резюме, ведение
профессиональной ленты сообщений и справочно-информационные разделы.

Программное обеспечение является самостоятельным продуктом и не является
модификацией, надстройкой или локализацией иного программного обеспечения.

## 2. Архитектура

Программное обеспечение построено по клиент-серверной архитектуре и разделено
на независимо развёртываемые компоненты, объединённые в монорепозиторий:

| Компонент | Назначение | Технология |
|---|---|---|
| `apps/api` | Сервер приложений, REST API (139 методов), бизнес-логика | Node.js 22, Express, TypeScript |
| `apps/web` | Публичная витрина с серверным рендерингом | Next.js 15, React 19 |
| `apps/admin` | Административная панель | React 19, Vite |
| `packages/db` | Схема базы данных, миграции, репозитории | PostgreSQL 16, Drizzle ORM |
| `packages/shared` | Схемы валидации и контракты данных | TypeScript, Zod |
| `packages/ui` | Общие элементы пользовательского интерфейса | React |

Взаимодействие клиентских приложений с сервером осуществляется по протоколу
HTTPS через документированный REST API версии `v1`. Спецификация интерфейса
формируется в формате OpenAPI 3.1 и доступна по адресу `/api/v1/openapi.json`.

Контракты данных описаны декларативно и используются одновременно для валидации
входящих запросов на сервере и для типизации клиентского кода, что исключает
рассогласование между составными частями системы.

## 3. Функциональные возможности

### 3.1. Каталог и поиск

Иерархический каталог категорий и товарных позиций. Карточка товара содержит
характеристики, изображения, сведения о продавце и отзывы. Полнотекстовый поиск
с морфологией и фильтрацией реализован на поисковом движке Meilisearch.

### 3.2. Оформление заказа

Корзина с изменением состава и количества позиций, оформление заказа,
отслеживание жизненного цикла заказа обеими сторонами сделки.

### 3.3. Личный кабинет покупателя

Управление профилем и учётными данными, история и статусы заказов, уведомления,
реферальная программа, реестр эксплуатируемой техники с подбором запасных частей,
резюме с приложением документов и отклики на вакансии.

### 3.4. Кабинет продавца

Публикация и редактирование товарных позиций с загрузкой изображений, обработка
поступивших заказов, публичная страница компании, публикация вакансий
и рассмотрение поступивших откликов.

### 3.5. Тендерные процедуры

Создание закупочной процедуры, её публикация, приём предложений от поставщиков,
рассмотрение и отзыв предложений, определение победителя, закрытие, отмена
и завершение процедуры.

### 3.6. Отзывы и репутация

Публикация отзывов о товарах с последующей модерацией, верификация продавцов
и пользователей администратором.

### 3.7. Профессиональная лента

Публикации пользователей и компаний, комментарии, отметки «нравится», подписки
на пользователей и компании, персональная лента подписок, механизм жалоб
на публикации.

### 3.8. Вакансии и резюме

Каталог вакансий с рубрикацией, база резюме, приложение документов к резюме,
отклики соискателей и их рассмотрение работодателем.

### 3.9. Информационные разделы

Публикация статей и информационных материалов с рубрикацией, редактирование
через административную панель.

### 3.10. Административная панель

Управление пользователями, продавцами, товарами, заказами, отзывами, резюме,
вакансиями и публикациями; рассмотрение жалоб; верификация участников;
сводная статистика площадки.

### 3.11. Управление доступом

Регистрация и аутентификация, подтверждение адреса электронной почты,
восстановление и смена пароля, разграничение прав доступа по ролям
(покупатель, продавец, администратор), ведение журнала действий.

## 4. Требования к аппаратному и программному обеспечению

### 4.1. Серверная часть

| Параметр | Минимально | Рекомендуется |
|---|---|---|
| Процессор | x86-64, 4 ядра | 8 ядер |
| Оперативная память | 8 ГБ | 16 ГБ |
| Дисковое пространство | 40 ГБ SSD | 100 ГБ SSD |
| Операционная система | Linux с ядром 5.x и новее | Ubuntu 22.04 LTS, Debian 12, Astra Linux Special Edition |

Общесистемное программное обеспечение: Docker Engine 24.0 и новее, Docker Compose
версии 2. При развёртывании без контейнеризации дополнительно требуются
Node.js 22 LTS, PostgreSQL 16, Redis 7, Meilisearch 1.x и S3-совместимое
объектное хранилище.

Всё перечисленное общесистемное программное обеспечение распространяется
на условиях свободных лицензий и не требует платежей иностранным лицам.
PostgreSQL допускает замену на Postgres Pro без изменения исходного кода.

### 4.2. Клиентская часть

Персональный компьютер или мобильное устройство с браузером, поддерживающим
стандарты HTML5, CSS3 и ECMAScript 2020: Яндекс Браузер, Google Chrome 111
и новее, Mozilla Firefox 110 и новее, Microsoft Edge 111 и новее, Safari 16
и новее. Установка дополнительного программного обеспечения на рабочем месте
пользователя не требуется.

доступа с ограниченным сроком действия и раздельным механизмом обновления
сессии. Пароли хранятся в виде необратимых криптографических свёрток.

противодействия подбору учётных данных. Все действия, изменяющие состояние
системы, фиксируются в журнале аудита. Разграничение доступа осуществляется
на основании ролевой модели.

Обработка персональных данных пользователей осуществляется в соответствии
с Федеральным законом от 27.07.2006 № 152-ФЗ. Данные размещаются в базе данных,
находящейся на территории Российской Федерации.
