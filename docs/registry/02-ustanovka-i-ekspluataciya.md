# Информация, необходимая для установки и эксплуатации программного обеспечения

**Наименование:** «China.ru — маркетплейс промышленного оборудования из Китая»

**Правообладатель:** ООО «Чайна.Ру»

**Версия:** 1.0

---

## 1. Общие сведения

Программное обеспечение поставляется в виде исходного кода и файлов описания
контейнеров. Установка выполняется на сервере заказчика и не требует обращения
к внешним сервисам правообладателя. Все компоненты, необходимые для работы,
разворачиваются локально средствами Docker Compose.

Установка выполняется системным администратором, обладающим базовыми навыками
работы с операционной системой Linux и системой контейнеризации Docker.

## 2. Подготовка сервера

1. Установить операционную систему из числа поддерживаемых (раздел 4.1 документа
   «Описание функциональных характеристик»).
2. Установить Docker Engine версии 24.0 и новее и Docker Compose версии 2.
3. Обеспечить сетевую доступность сервера по протоколам HTTP (порт 80)
   и HTTPS (порт 443).
4. Настроить записи системы доменных имён для доменов витрины,
   программного интерфейса и административной панели, указав их на IP-адрес
   сервера.

Проверка готовности:

```bash
docker --version
docker compose version
```

## 3. Установка

### 3.1. Получение дистрибутива

```bash
git clone <адрес репозитория> china-ru
cd china-ru
```

### 3.2. Настройка параметров

```bash
cp .env.prod.example .env.prod
```

Файл `.env.prod` содержит параметры развёртывания. Обязательному заполнению
подлежат:

| Параметр | Назначение |
|---|---|
| `WEB_HOST`, `API_HOST`, `ADMIN_HOST` | Доменные имена витрины, программного интерфейса и административной панели. Подставляются в конфигурацию веб-сервера при запуске |
| `CERT_NAME` | Имя каталога сертификата в `/etc/letsencrypt/live/` |
| `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_SITE_URL`, `API_PUBLIC_URL`, `WEB_URL`, `ADMIN_URL` | Публичные адреса компонентов |
| `COOKIE_DOMAIN` | Общий родительский домен для файлов cookie |
| `POSTGRES_USER`, `POSTGRES_PASSWORD` | Учётные данные базы данных |
| `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` | Ключи подписи токенов, не менее 32 символов |
| `MEILI_MASTER_KEY` | Ключ доступа к поисковому индексу |
| `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD` | Учётные данные объектного хранилища |
| `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` | Параметры файлового хранилища |

Незаполненный обязательный параметр останавливает запуск с указанием
недостающего имени. Значения по умолчанию для доменов не предусмотрены
намеренно: развёртывание с чужим доменом в конфигурации веб-сервера
внешне выглядит успешным, но не отвечает ни на один запрос.

Параметры `NEXT_PUBLIC_API_URL` и `NEXT_PUBLIC_SITE_URL` включаются
в сборку клиентского приложения. Их изменение требует пересборки образа,
перезапуска контейнера недостаточно.

Ключи подписи токенов рекомендуется формировать средствами операционной системы:

```bash
openssl rand -hex 32
```

Файл `.env.prod` содержит сведения ограниченного доступа и не подлежит передаче
третьим лицам и размещению в системе контроля версий.

### 3.3. Выпуск сертификатов TLS

```bash
docker run --rm -v /etc/letsencrypt:/etc/letsencrypt \
  -v china-ru_certbot_webroot:/var/www/certbot certbot/certbot certonly \
  --webroot -w /var/www/certbot \
  -d china-ru.ru -d www.china-ru.ru -d api.china-ru.ru -d admin.china-ru.ru
```

Домены указываются в соответствии с фактическим развёртыванием и должны
совпадать со значениями `WEB_HOST`, `API_HOST` и `ADMIN_HOST`. Имя каталога,
который создаст certbot, определяется первым доменом в команде — его
и следует указать в `CERT_NAME`. Допускается
использование сертификатов, выпущенных иным удостоверяющим центром, — в этом
случае файлы сертификата и закрытого ключа размещаются в каталоге
`/etc/letsencrypt` в структуре, ожидаемой конфигурацией веб-сервера.

### 3.4. Запуск

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
```

Команда выполняет сборку образов приложений, запуск базы данных, кеша,
поискового индекса, объектного хранилища, сервера приложений, витрины,
административной панели и пограничного веб-сервера.

Миграции базы данных применяются автоматически при первом запуске сервера
приложений. Ручное применение миграций:

```bash
npm run db:migrate -w @china-ru/db
```

### 3.5. Проверка работоспособности

| Проверка | Ожидаемый результат |
|---|---|
| `docker compose -f docker-compose.prod.yml ps` | Все службы в состоянии `running` |
| Запрос `GET /api/health` | Ответ с кодом 200 |
| Открытие адреса витрины в браузере | Отображается главная страница |
| Открытие адреса административной панели | Отображается форма входа |
| Запрос `GET /api/v1/openapi.json` | Возвращается спецификация интерфейса |

## 4. Эксплуатация

### 4.1. Роли пользователей

| Роль | Доступные возможности |
|---|---|
| Покупатель | Каталог, корзина, заказы, тендеры, отклики на вакансии, лента, профиль |
| Продавец | Возможности покупателя, а также товары, обработка заказов, страница компании, вакансии |
| Администратор | Административная панель, модерация, верификация участников, статистика |

### 4.2. Начало работы

Первичная учётная запись администратора создаётся при развёртывании средствами
сценария наполнения базы данных либо назначением роли существующему пользователю
непосредственно в базе данных. После входа в административную панель дальнейшее
управление участниками осуществляется через интерфейс.

Пользователи регистрируются самостоятельно через форму на витрине с последующим
подтверждением адреса электронной почты. Статус продавца присваивается
администратором после верификации сведений об организации.

### 4.3. Регламентные работы

| Работа | Периодичность | Действие |
|---|---|---|
| Резервное копирование базы данных | Ежесуточно | `pg_dump` с выгрузкой на отдельный носитель |
| Резервное копирование файлового хранилища | Ежесуточно | Копирование содержимого хранилища объектов |
| Обновление сертификатов TLS | Каждые 60 суток | Продление средствами certbot |
| Контроль свободного дискового пространства | Еженедельно | Не менее 20 % свободного объёма |
| Просмотр журналов | Еженедельно | `docker compose logs` по компонентам |

### 4.4. Обновление версии

```bash
git fetch --tags
git checkout <версия>
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
```

Перед обновлением выполняется резервное копирование базы данных. Миграции
применяются автоматически при старте обновлённого сервера приложений.

### 4.5. Остановка и удаление

```bash
docker compose -f docker-compose.prod.yml down          # остановка
docker compose -f docker-compose.prod.yml down -v       # остановка с удалением данных
```

## 5. Типовые неисправности

| Признак | Вероятная причина | Устранение |
|---|---|---|
| Витрина недоступна, `/api/health` не отвечает | Не запущен сервер приложений | Просмотреть `docker compose logs api`, проверить параметры подключения к базе данных |
| Ошибка входа при верных учётных данных | Не заданы или изменены ключи подписи токенов | Проверить `JWT_ACCESS_SECRET` и `JWT_REFRESH_SECRET` в `.env.prod` |
| Не отображаются изображения товаров | Недоступно объектное хранилище | Проверить состояние службы хранилища и параметры `S3_*` |
| Поиск не возвращает результатов | Не построен поисковый индекс | Перезапустить службу индексации, выполнить переиндексацию каталога |
| Предупреждение браузера о сертификате | Истёк срок действия сертификата | Продлить сертификат и перезапустить пограничный веб-сервер |

При невозможности устранить неисправность собственными силами заказчик
обращается в службу технической поддержки правообладателя в порядке,
установленном документом «Описание процессов, обеспечивающих поддержание
жизненного цикла программного обеспечения».
