# ADR 0001 — Вести Architecture Decision Records

- **Статус:** принято
- **Дата:** 2026-06-12

## Контекст

Проект готовится к техническому due‑diligence инвесторов и к включению в Реестр
российского ПО. Архитектурные решения должны быть прослеживаемы и обоснованы.

## Решение

Ведём ADR в `docs/adr/` в формате Майкла Нейгарда: один файл на решение,
нумерация по возрастанию, поля «Контекст / Решение / Последствия». ADR неизменяемы;
изменение решения оформляется новым ADR со ссылкой «Supersedes».

## Последствия

- Любое значимое архитектурное решение фиксируется отдельным ADR.
- Аудитор видит историю и мотивацию решений, а не только итоговый код.
