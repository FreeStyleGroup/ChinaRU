# ADR 0004 — API-слой: Express, DI, auth и единый конверт ответа

- **Статус:** принято
- **Дата:** 2026-06-12

## Контекст

Нужен HTTP-API над слоем данных (R1) и контрактами (R2): для веба, админки и
будущих мобильных приложений (Kotlin/Swift). Требования инвест-уровня: строгая
типизация без `any`, тестируемость без Docker, безопасная авторизация, отсутствие
антипаттернов прошлого MVP (`this` в объект-литералах сервисов, дыры в RBAC,
рассинхрон валидации).

## Решение

1. **Express 5 + классы с DI.** Сервисы и репозитории — классы, принимающие
   зависимости в конструктор; композиционный корень (`container.ts`) собирает
   репозитории → сервисы → контроллеры из одного `Database`. Никаких
   объект-литералов с `this`, никаких глобальных синглтонов в бизнес-логике.
2. **Фабрика приложения `createApp({ db, config, logger, mailer? })`.** Позволяет
   в тестах подменить БД (PGlite) и транспорт писем. Точка входа `server.ts`
   валидирует env (Zod), поднимает пул postgres.js и слушает порт.
3. **Валидация — схемами R2 прямо в контроллере** (`schema.parse(req.body)`).
   `ZodError` ловится единым errorHandler и отдаётся как `422` с картой ошибок по
   полям. Один источник правды для БД, API и клиентов.
4. **Единый конверт ответа `ApiResponse`** (`ok`/`err` из `@china-ru/shared`) на
   всех маршрутах, включая 404 и 429. Доменные ошибки (`AppError`, `OrderError`)
   маппятся на осмысленные статусы; непредвиденное — `500` без утечки деталей.
5. **Auth: JWT access + rotating refresh.** Refresh хранится sha256-хешем в БД,
   ротация с детектом повторного использования (рвёт всю цепочку токенов).
   httpOnly-cookies для веба (refresh — на узком пути `/api/v1/auth`), `Bearer`
   - refresh в теле для мобильных (TTL 90 дней). bcrypt cost ≥ 12. RBAC —
     `requireRole`. Анти-энумерация на login/reset.
6. **Безопасность по умолчанию:** helmet, CORS allowlist с credentials,
   глобальный rate-limit + усиленный на auth-маршрутах, `trust proxy`.
7. **OpenAPI 3.1** отдаётся на `/api/v1/openapi.json` — контракт для Swagger UI и
   генерации мобильных SDK.
8. **Тесты — supertest поверх PGlite**, без Docker: проходят весь стек
   (роут → контроллер → сервис → репозиторий → SQL), включая регистрацию/сессию,
   каталог и создание заказа со списанием стока.

## Последствия

- Прод-сборка — один бандл (`tsup`, ESM, Node 22), workspace-пакеты инлайнятся.
- Добавление домена = репозиторий (R1) + схемы (R2) + сервис + контроллер + роут,
  по уже зафиксированному шаблону. Остальные домены (seller CRUD, reviews, chat,
  travel, jobs, metro, devices, notifications) подключаются в этом ритме.
- `dist/` и секреты — вне репозитория; конфиг падает на старте при плохом env.
