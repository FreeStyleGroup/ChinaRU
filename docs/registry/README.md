## 🔥 Документы обязаны быть опубликованы в открытом доступе

Заявление в реестр требует **адрес страницы в сети Интернет**, по которому
документация доступна для свободного скачивания без регистрации. Файл, лежащий
только в приватном репозитории, требование не закрывает — заявление вернут.

Разместить документы 01–04 по постоянным адресам на **china-ru.ru**:

| Документ | Адрес публикации |
|---|---|
| 01 Функциональные характеристики | `https://china-ru.ru/reestr-po/funkcionalnye-harakteristiki/` |
| 02 Установка и эксплуатация | `https://china-ru.ru/reestr-po/ustanovka-i-ekspluataciya/` |

| 04 Стоимость | `https://china-ru.ru/reestr-po/stoimost/` |

Адреса не должны меняться при выпуске новых версий: они попадают в карточку
реестра, и битая ссылка там — повод для исключения сведений.

### Как опубликовать

Страницы собираются из этих же .md — руками их верстать не надо и НЕЛЬЗЯ:
две копии одного текста разъезжаются на первой правке, и разъехавшуюся
заметит проверяющий, а не мы.

```
node docs/registry/build-site-pages.mjs
```

Получится готовая папка `out/site/reestr-po/` — залить её целиком в корень
сайта china-ru.ru (сайт на Битриксе, репозиторий `D:/Claude/China-Bitrix`).

```
out/site/reestr-po/  →  <корень сайта>/reestr-po/
  index.php                        оглавление
  funkcionalnye-harakteristiki/index.php
  ustanovka-i-ekspluataciya/index.php
  zhiznennyy-cikl-i-podderzhka/index.php
  stoimost/index.php
  regdoc.css                       стили раздела
  .htaccess                        запрет листинга каталога
```

Страницы обычные битриксовые: `bitrix/header.php`, содержимое, `bitrix/footer.php`.
Ни компонента, ни инфоблока, ни правок шаблона не требуется — раздел
переносится одной папкой и живёт сам по себе.

🔥 Адрес выбран `/reestr-po/`, а не `/docs/`: в репозитории China-Bitrix
папка `docs/` занята внутренней документацией по архитектуре, и раздел
с таким именем на сайте однажды выложил бы её наружу.

После заливки проверить: все пять адресов открываются без авторизации,
в приватном окне и с телефона. Требование реестра — свободный доступ.


## Порядок подачи

1. **Сначала свидетельство Роспатента.** Оно не является обязательным условием
   для реестра по букве ПП № 1236, но снимает вопрос подтверждения прав
   и заметно упрощает рассмотрение. Пакет — в `../registration/`.
2. ✅ Модель стоимости выбрана: безвозмездно, доход правообладателя — комиссия за сделки.
3. Опубликовать документы 01–04 в открытом доступе.
4. Подать заявление через ЕПГУ (Госуслуги) с УКЭП юридического лица.
5. Указать класс ПО по классификатору Минцифры. Профиль продукта — прикладное
   ПО для электронной коммерции и торговых площадок. ⏳ Конкретный код класса
   выбрать в действующей редакции классификатора при заполнении формы.

## ⚠️ Риски, которые надо снять до подачи

### 1. Лицензии инфраструктурных образов

SBOM покрывает **прямые prod-зависимости кода** (24 пакета) — и там действительно
чисто. Но в `docker-compose.prod.yml` поставляются ещё и сторонние сервисы,
и по ним картина другая:

| Образ | Лицензия | Проблема |
|---|---|---|
| `minio/minio:latest` | AGPL-3.0 | Копилефт. Продукт обращается к нему по сетевому S3-протоколу, не линкуется и не модифицирует его, поэтому на код продукта обязательства AGPL не распространяются — но образ входит в поставку, и вопрос на рассмотрении задать могут |
| `redis:7-alpine` | ⏳ проверить | С версии 7.4 (март 2024) Redis распространяется под RSALv2 + SSPL, а не BSD. SSPL — ровно та лицензия, отсутствие которой утверждает SBOM. Нужно установить, какая версия стоит за плавающим тегом |
| `postgres:16-alpine` | PostgreSQL License | Разрешительная, вопросов нет |
| `getmeili/meilisearch:v1.8` | MIT | Вопросов нет |
| `nginx:1.27-alpine` | BSD-2-Clause | Вопросов нет |

**Что сделать:**

- **Redis → Valkey.** Форк под BSD-3-Clause под управлением Linux Foundation,
  совместим по протоколу, замена сводится к смене образа.
- **MinIO** — либо оставить и описать в документации как отдельный сетевой сервис,
  не входящий в состав программы, либо заменить на SeaweedFS (Apache-2.0).
  Решение за правообладателем; первый путь дешевле, второй снимает вопрос совсем.
- **Зафиксировать точные версии образов.** Плавающие теги `latest` и `7-alpine`
  означают, что завтра за тем же тегом окажется другой продукт с другой лицензией.
  Для реестра это хуже вдвойне: заявленный состав перестаёт совпадать с фактическим,
  а сверить рабочий экземпляр с задекларированным реестр вправе.

### 2. SBOM не покрывает транзитивные зависимости

Сейчас в отчёте только прямые. Полное дерево не сканировалось, и утверждать,
что копилефта нет во всей поставке, оснований нет. До подачи прогнать проверку
по всему дереву и включить результат в SBOM.

### 3. Домен в примерах развёртывания не тот

`.env.prod.example`, `docker-compose.prod.yml` и `docs/deploy.md` построены
вокруг `china.ru`, тогда как рабочий домен правообладателя — **china-ru.ru**
(он же в коде: `HOROSCOPE_IMAGE_BASE = https://china-ru.ru/upload/horoscope`).
Домен `china.ru` правообладателю не принадлежит. В документации реестра
везде проставлен china-ru.ru, но примеры в репозитории надо привести
к тому же домену: проверяющий сверяет заявленное с фактическим.

### 4. README репозитория устарел

В нём написано «фаза R0 — фундамент», хотя реализованы R0–R7 и коммерческое ядро.
Документ публичный и в глазах проверяющего описывает продукт как заготовку.
