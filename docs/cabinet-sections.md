## Идентификация и верификация (сквозная логика)

- **Числовой публичный ID по умолчанию.** Пользователю при регистрации присваивается
  числовой `publicId` (с 100001); магазину при создании — свой числовой `publicId`.
  Отображается как `ID 100001` / `#100001`.
- **Никнейм — после верификации.** Верифицированный пользователь может выбрать
  никнейм (`@nickname`), он заменяет числовой ID. Так же и магазин — после
  верификации появляется возможность выбрать/сменить никнейм. Никнеймы уникальны.
- **Синяя галочка.** Пользователь верифицируется модератором (`users.verifiedAt`);
  магазин — через статус заявки (`verifyStatus = verified`). Галочка — рядом с
  именем/названием.
- **Где в кабинете:** в Профиле блок «Никнейм» виден всегда; если профиль не
  верифицирован — **серый/неактивный** с кружком‑подсказкой (ⓘ). Аналогичный блок —
  в кабинете магазина после подтверждения.
- **Админка (модерация):** отдельный раздел верификации **пользователей**
  (`POST /admin/users/:id/verify`) и отдельный — **компаний/магазинов**
  (`POST /admin/sellers/:id/verify`). _UI админ‑SPA — следующий шаг; контракты и
  логика уже заложены._

## Профиль

- Аватар (клик для замены, JPG/PNG/WebP, ≤ 2 МБ).
- Шапка: имя + **синяя галочка** (если верифицирован) + `ID <publicId>` или `@nickname`.
- Поля: **Имя**, **Фамилия**, **Дата рождения** (date), **Телефон**, **Email**.
- **Дата рождения** питает раздел **Гороскоп** (китайский знак зодиака).
- Блок **Никнейм**: всегда виден; неактивен/серый с ⓘ до верификации.
- Блок **Смена пароля**: Текущий + Новый (≥ 6) + Подтверждение (рвёт сессию → relogin).
- Кнопка **Сохранить**.
- Подразделы: **Карты оплаты**, **Адрес доставки** (отдельные экраны).

### MLM-движок ✅ (реализован)

- **Реф-ссылка** у каждого: `china.ru/register?ref=<publicId>`, промокод `CN-XXXXXX`.
  Регистрация по ссылке привязывает пригласившего (`users.referredBy`).
- **Начисления** автоматом при оплате заказа реферала вверх по цепочке (3 уровня):
  деньги **10/5/2 %** + баллы (10/3/1 на каждые 100 ₽), плюс **разовый бонус 500
  баллов** прямому пригласившему за первую сделку реферала. Леджер `referral_earnings`.
- **Баланс:** `users.points` (баллы) + `users.referralBalance` (₽) — тратятся на
  портале (без вывода, по решению заказчика). Эндпоинт `GET /account/referral`
  (сводка: ссылка, балансы, агрегаты, партнёры по уровням). Тест `referral.test.ts`.
- **Триггеры (заложены):** заказ (готово), подписка/услуга и первая сделка —
  через `ReferralService.accrue(event, …)`; подписку подключим с биллингом Консьержа.

## Мой магазин (кабинет продавца) — поток открытия

**Любой пользователь может стать продавцом.** Пункт меню и содержимое зависят от
статуса заявки (`verifyStatus`):

1. **Нет заявки / unverified → «Начать торговать».** Форма регистрации магазина:
   Название компании\*, на китайском, форма (ООО/ИП/Co.,Ltd), **ИНН\***,
   **контактный email\***, **контактный телефон\***, О компании. ИНН + почта +
   телефон обязательны и **уходят модератору на проверку**. Кнопка «Отправить на
   модерацию» → `verifyStatus = pending`.
2. **pending → «Мой магазин» / экран «Заявка на модерации»** (показывает `#publicId`
   и название). Повторная подача — только после отклонения.
3. **rejected →** снова форма с плашкой «Заявка отклонена, отправьте повторно».
4. **verified →** открывается кабинет продавца (Обзор). Появляется синяя галочка,
   роль пользователя повышается до `seller`, доступен блок **Никнейм магазина**
   (числовой `#publicId` → `@nickname`).

Кабинет (verified) — layout с верхними вкладками: **Обзор · Товары · Заказы ·
Магазин · Аналитика · Продвижение · Помощь**.

**Обзор:**

- **Финансы:** Общий баланс, Можно вывести (+ «Подробнее»).
- **Сообщения:** От пользователей (N), Системные (N) (+ «Все сообщения»).
- **Споры:** Новые, В процессе, Ждут возврата (+ «Перейти к спорам»).
- **Товары:** В продаже, Нет в наличии, Заблокировано, На рассмотрении, Нужно
  исправить, Снято с продажи (+ «Управление товарами»).
- **Ключевые метрики:** Просмотры, Посетители, Заказы, Выручка, CTR; переключатель
  периода (За сутки / За неделю / За месяц) + «Перейти в аналитику».

## Работа ✅ (модерация реализована)

- **Моё резюме (реальный API):** должность*, сфера (10 отраслей), зарплата, опыт,
  навыки, о себе, подтверждённый **HSK**; **шкала заполненности** (% по заполненным
  полям); **рейтинг соискателя**. Любое сохранение → статус **«На проверке»** →
  модератор публикует (видно в «Вакансии») / отклоняет с причиной.
- **Вакансии:** размещает только **верифицированная компания** → статус pending →
  после модерации попадают в публичный листинг `/jobs`.
- **Рейтинг соискателя** растёт за подтверждённые документы/сертификаты, в т.ч.
  **сертификат HSK нашей школы** (загрузка документов — следующий шаг, нужен MinIO).
- **Бэкенд:** таблица `resumes` + moderation на `job_listings`; enum
  `moderation_status` (pending/published/rejected), `job_category`, `resume_experience`.
  Эндпоинты: `GET/PUT /account/resume`, `GET /jobs`, `POST /seller/vacancies`,
  `GET/POST /admin/{resumes,vacancies}[/:id/moderate]`. Админ-SPA: разделы «Резюме» и
  «Вакансии» (Опубликовать/Отклонить). Тесты: api `jobs.test.ts` (34 api всего).
- **Рейтинг компаний** — на `seller_profiles.rating` (уже есть).
- **Впереди:** публичная вертикаль «Работа в Китае» (hero, горячие вакансии,
  категории-сетка, ведущие компании, города), отклики (applications), загрузка
  документов резюме.

## Гороскоп

- Определяет **китайский знак зодиака** по дате рождения из Профиля
  (`chineseZodiac()` в `@china-ru/shared`): эмодзи, знак, стихия, черты.
- Прогноз на сегодня (Любовь/Карьера/Финансы/Здоровье) — пока демонстрационный.
- Если дата рождения не указана — CTA «Заполнить дату рождения» → Профиль.

- **Афиша уточнена:** Активные = **купленные билеты** (бейдж «Билетов: N»), Избранное =
  **wishlist**, Архив = прошедшие. По **«Напомнить»** — модалка «Напоминание»: дата/время
  + тумблеры каналов **СМС / В приложении / По почте** (Отмена/Сохранить).

## Социальная сеть

- Лента/посты пользователя (композер + посты, лайки/комментарии).
- **Компании (магазины) имеют отдельную страницу** для размещения постов

## Тендеры

- Отражает тендеры пользователя/компании: вкладки **Мои заявки** (участие + статус:
  На рассмотрении/Принята/Отклонена/Победа) и **Мои тендеры** (размещённые). Логику
  площадки (типы, ставки, переходы) заказчик опишет отдельно.

## Грузоперевозки

- Отражает перевозки: **Активные перевозки** (маршрут, тип, **трек-номер, статус,
  прогресс, ETA**) и **Мои объявления**. Статусы: Ожидает/В пути/На таможне/Доставлено.

## Обучение

- Пользователь добавлен в **группу** (общую/индивидуальную): карточка группы

  **домашние задания** (срок, статус Сдано/Не сдано). Связано со «Школой» (`/school/`).

## Консьерж
